# Getting started

## Requirements

- Node.js 24, or 26 and later
- Vitest 5
- [`@cucumber/cucumber`](https://github.com/cucumber/cucumber-js) 13

The package is ESM only: your Vitest config must load as an ES module (`"type": "module"` in the
nearest `package.json`, or a `vitest.config.mts`).

### Configure Vitest

```ts filename="vitest.config.ts"
import { cucumber } from "@lotun/vitest-cucumber";
import { defineConfig } from "vitest/config";

export default defineConfig({
  plugins: [
    cucumber({
      // Your step definitions, hooks and World
      import: ["features/**/*.ts"],
    }),
  ],
  test: {
    // Your feature files
    include: ["features/**/*.feature"],
  },
});
```

<Callout type="warning">
  Both are required. Without `test.include`, Vitest looks for its default
  `*.test.ts` files and finds no feature files. Without `import`, Vitest
  doesn't start: `the "import" option is missing, give it your support code's globs`.
</Callout>

To keep the options in a file of their own, import them from it:
[Where the options go](/reference/options#where-the-options-go).

### Add the plugin's types

In a TypeScript project, name the plugin's types in the `tsconfig.json` that checks your support
code:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "types": ["@lotun/vitest-cucumber"]
  }
}
```

They type Cucumber's hooks for arrow functions that take the World, the way the steps below are
written: [TypeScript](/guides/support-code#typescript).

### Write a feature

```gherkin filename="features/calculator.feature"
Feature: Calculator

  Scenario: Adding two numbers
    Given the number 2
    When I add 3
    Then the result is 5
```

### Write its steps

```ts filename="features/steps/calculator.ts"
import {
  Given,
  setWorldConstructor,
  Then,
  When,
  World,
} from "@cucumber/cucumber";
import { expect } from "vitest";

class Calculator extends World {
  result = 0;
}

setWorldConstructor(Calculator);

Given("the number {int}", (world: Calculator, n: number) => {
  world.result = n;
});

When("I add {int}", (world: Calculator, n: number) => {
  world.result += n;
});

Then("the result is {int}", (world: Calculator, expected: number) => {
  expect(world.result).toBe(expected);
});
```

Each scenario gets a new `Calculator`, its [World](/guides/support-code#world): the place to keep
state between steps. A step gets it as its first argument when that parameter is named `world`.
Cucumber's own form, a `function` with the World as `this`, works too:
[World in an arrow function](/guides/support-code#world-in-an-arrow-function).

Any assertion library works; Vitest's `expect` gives you its diffs.

### Run

```bash
npx vitest        # watch mode
npx vitest run    # once
```
