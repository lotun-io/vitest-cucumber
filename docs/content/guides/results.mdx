# Results and failures

Vitest reports every scenario. There's no separate Cucumber output: a scenario's result, Cucumber's
summary of what went wrong and its snippets are in the test's result, in any Vitest reporter
(default, verbose, JUnit, JSON, HTML, the UI).

## Statuses

| Cucumber           | Vitest                                                                 |
| ------------------ | ---------------------------------------------------------------------- |
| passed             | passed                                                                 |
| failed             | failed, with the step's error                                          |
| undefined          | failed, with Cucumber's summary and snippets                           |
| ambiguous          | failed, with the matching definitions                                  |
| pending            | failed; with [`strict: false`](/reference/options#strict): skipped     |
| skipped            | skipped (a step or hook returned `"skipped"`)                          |

The run fails as Vitest's does: a failed test, a feature file that can't load, or a failing
`BeforeAll` / `AfterAll`.

## A failing step

The error is your error, as Vitest prints it (`expect`'s diff, the error's name and `cause`), and the
code frame points at the step's line in the feature file before your own frames:

```ansi
[41m[1m FAIL [22m[49m features/cart.feature[2m:2[22m[2m > [22mCart[2m > [22mAdding an item
[31m[1mAssertionError[22m: expected +0 to be 1 // Object.is equality[39m

[32m- Expected[39m
[31m+ Received[39m

[32m- 1[39m
[31m+ 0[39m

[36m [2m❯[22m features/cart.feature:[2m5:5[22m[39m
    [90m  3|[39m     Given an empty cart
    [90m  4|[39m     When I add "apples"
    [90m  5|[39m     Then the cart has 1 item
    [90m   |[39m     [31m^[39m
    [90m  6|[39m
    [90m  7|[39m   Scenario: Adding pears
[90m [2m❯[22m World.<anonymous> features/steps/cart.ts:[2m11:29[22m[39m[0m
```

- The test's header is the scenario's line (an example's: its row's line).
- An `And` step, a step with a data table or doc string, a Background step: each at its own line.
- Cucumber's and the plugin's own frames are hidden; [`backtrace: true`](/reference/options#backtrace)
  shows them.
- A thrown value that isn't an `Error` (a string, an object, `null`) becomes an error named by the
  step's text, with the value as its `cause`. In a hook: `Before hook failed`, `After hook failed`.
- An `AggregateError` shows each of its errors.
- An error thrown by a timer while an async step runs fails that step.

## Undefined, pending and ambiguous steps

The test's error is the step's text, followed by the scenario's summary, as Cucumber's summary
formatter prints it.

**An undefined step**: no definition matches.

```ansi
[41m[1m FAIL [22m[49m features/checkout.feature[2m:2[22m[2m > [22mCheckout[2m > [22mPaying by card
[31m[1mError[22m: When I pay with "card"

[34mUndefined steps:[31m
  [34m[1mWhen [22mI pay with "card"[31m

You can implement missing steps with the snippets below:

When('I pay with {string}', function (string) {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});[0m
```

**A pending step**: its definition returned `"pending"`.

```ansi
[41m[1m FAIL [22m[49m features/checkout.feature[2m:6[22m[2m > [22mCheckout[2m > [22mUsing a coupon
[31m[1mError[22m: When I apply the coupon "SAVE10"

[36mPending steps:[31m
  [36m[1mWhen [22mI apply the coupon [1m"SAVE10"[22m[31m [90m# features/steps/checkout.ts:5[31m[39m[0m
```

**An ambiguous step**: more than one definition matches.

```ansi
[41m[1m FAIL [22m[49m features/checkout.feature[2m:10[22m[2m > [22mCheckout[2m > [22mChecking the total
[31m[1mError[22m: Then the total is 5

[35mAmbiguous steps:[31m
  [35m[1mThen [22mthe total is 5[31m
      Multiple matching step definitions found:
        • the total is {int} [90m# features/steps/checkout.ts:9[31m
        • ^the total is (\d+)$ [90m# features/steps/checkout.ts:11[31m[39m[0m
```

**An undefined parameter type**: a definition uses `{currency}`, which nothing defines.

```ansi
[41m[1m FAIL [22m[49m features/checkout.feature[2m:14[22m[2m > [22mCheckout[2m > [22mPaying in another currency
[31m[1mError[22m: When I pay in euro

[34mUndefined steps:[31m
  [34m[1mWhen [22mI pay in euro[31m

[34mThese parameters are missing a parameter type definition:[31m
  'currency' in 'I pay in {currency}'

You can implement missing steps with the snippets below:

When('I pay in euro', function () {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});[0m
```

A scenario with several of these has one summary, in Cucumber's order: `Pending steps:`,
`Undefined steps:`, `Ambiguous steps:`, the parameter types used but not defined, then the
snippets. It's in color when Vitest's output is.

## Attachments

`this.log(text)`, `this.link(url)` and `this.attach(data, mediaType)` become the test's
[annotations](https://vitest.dev/guide/test-annotations), in the order they ran, hooks included:

```ts filename="features/steps/checkout.ts"
When("I pay with {string}", function (method: string) {
  this.log(`Paying with ${method}`);
  this.link("https://example.com/orders/42");
  this.attach(JSON.stringify({ total: 5 }), "application/json");
});
```

Vitest prints them when a test fails. To see them for every test, passing ones too, use its
verbose reporter:

```bash
npx vitest run --reporter=verbose
```

```ansi
 [32m✓[39m features/checkout.feature[2m:2[22m[2m > [22mCheckout[2m > [22mPaying by card[32m 11[2mms[22m[39m

   [34m❯[39m [1mlog[22m
     [34m↳[39m Paying with card
   [34m❯[39m [1mlink[22m
     [34m↳[39m https://example.com/orders/42
   [34m❯[39m [1mattachment[22m
     [34m↳[39m application/json[0m
```

| Call                          | Annotation                                             |
| ----------------------------- | ------------------------------------------------------ |
| `this.log("text")`            | type `log`, the text                                   |
| `this.link("https://…")`      | type `link`, the URL                                   |
| `this.attach(data, type)`     | type `attachment`, the file name or media type, data attached |

The JUnit and HTML reporters and Vitest's UI include them too. A retried scenario keeps every
attempt's.

## When a file fails before its scenarios run

A feature file that doesn't parse, support code that throws while loading, a definition Cucumber
rejects, a failing `BeforeAll` or `AfterAll`: each message and what to do is in
[Troubleshooting](/guides/troubleshooting).
