# Troubleshooting

Most errors say what's wrong and what to do: the plugin's own start with `[@lotun/vitest-cucumber]`,
and an error in your own code points at its line. This page covers the rest: messages from Vitest or
Storybook that the plugin causes, and problems that print no error. Not here? Ask on
[Discord](https://discord.gg/dfJUkmEtAP) or in
[GitHub Discussions](https://github.com/lotun-io/vitest-cucumber/discussions): [Community](/community).

## Nothing runs

### No test files found

```ansi
[31mNo test files found, exiting with code 1
[39m
[2minclude: [22m[33m**/*.{test,spec}.?(c|m)[jt]s?(x)[39m
[2mexclude:  [22m[33m**/node_modules/**[2m, [22m**/.git/**[39m[0m
```

Vitest's default `include` matches `*.test.ts` and `*.spec.ts` files, not feature files. Add yours:

```ts filename="vitest.config.ts"
test: { include: ["features/**/*.feature"] },
```

### Every step is undefined

```ansi
[41m[1m FAIL [22m[49m features/cart.feature[2m:2[22m[2m > [22mCart[2m > [22mAdding an item
[31m[1mError[22m: Given an empty cart

[34mUndefined steps:[31m
  [34m[1mGiven [22man empty cart[31m
  [34m[1mWhen [22mI add "apples"[31m

You can implement missing steps with the snippets below:

Given('an empty cart', () => {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});

When('I add {string}', (string) => {
  // Write code here that turns the phrase above into concrete actions
  return 'pending';
});[0m
```

No support code was loaded: the [`import`](/reference/options#import) globs match no file (a typo, or
the step definitions are in another folder), so no step has a definition. Point `import` at your step
definitions:

```ts filename="vitest.config.ts"
plugins: [cucumber({ import: ["features/**/*.ts"] })],
```

### A feature file without scenarios

```ansi
[41m[1m FAIL [22m[49m features/cart.feature[2m [ features/cart.feature ][22m
[31m[1mError[22m: No test found in suite features/cart.feature[39m[0m
```

Each scenario is a Vitest test, so a feature file with none has no tests, and Vitest fails it. Add a
scenario, or leave the file out of `test.include` until it has one. To have such files pass instead
(features still being written), set Vitest's
[`passWithNoTests`](https://vitest.dev/config/passwithnotests):

```ts filename="vitest.config.ts"
test: { passWithNoTests: true },
```

## Browser mode and Storybook

### Vite reloads the page mid-run

```ansi
[2m10:24:31 AM[22m [33m[1m[vite][22m[39m [90m[2m(client)[22m[39m [32mdependency optimized: [33mreact[32m[39m
[2m10:24:31 AM[22m [33m[1m[vite][22m[39m [90m[2m(client)[22m[39m [32moptimized dependencies changed. reloading[39m
[33m
[1m[vitest][22m Vite unexpectedly reloaded a test. This may cause tests to fail, lead to flaky behaviour or duplicated test runs.
[39m[33mFor a stable experience, add the newly optimized dependencies to your config's [1m`optimizeDeps.include`[22m field manually.[0m
```

A package your steps import was found only while the run was going, so Vite optimized it then and
reloaded the page. Vite looks for the packages to optimize in the test files before the run, and a
feature file isn't JavaScript, so it can't see what your support code imports. CommonJS packages
(React, for one) are the ones it has to optimize. Tests may then fail, be flaky or run twice. Add the
package to [`optimizeDeps.include`](https://vite.dev/config/dep-optimization-options#optimizedeps-include),
so it's optimized before the run:

```ts filename="vitest.config.ts"
optimizeDeps: { include: ["react"] },
```

### A feature that can't be linked

```text
Error: [@lotun/vitest-cucumber] feature file can't be linked to stories
  - the scenario "Saying hello" names no story: a story step names its story (its stories file's, or "default": its meta)
    src/Greeting.feature:7
  - the feature names no stories file: a feature file names its stories file once, in its Background, with a stories file step
    src/Greeting.feature:1
```

The plugin links each scenario of a feature file to a story from its
[Storybook steps](/guides/storybook/stories-and-steps#storybook-steps), before anything runs. A link it can't
make fails the feature's stories, with every such error listed, each with the places it's about
under it (in Storybook's own process, it stops its index: `storybook dev` lists the error,
`storybook build` fails). Each error, and what to do:

| The error says | Do this |
| --- | --- |
| `names no stories file` | Name it in the feature's Background: `Given the stories of "./Greeting.stories.ts"` |
| `has no scenarios` | Give the feature a scenario: in Storybook, its scenarios are its stories |
| `has 2 stories file steps` | Keep one, in the Background: a feature runs on one stories file |
| `the stories file "…" doesn't exist` | Fix the path: from the feature's folder with `./` or `../`, else from the project's root |
| `names no story` | Give the scenario a story step: `Given the "Ada" story`, or `Given the "default" story` for the meta |
| `names no stories file` (a scenario) | Move the stories file step to the Background, so it reaches every scenario |
| `it has no steps` | A scenario without steps gets no Background steps: give it its own story step |
| `names a story twice` | Keep one story step per scenario, the Background's counted |
| `has no story "…"` | Name one of the stories it lists, as exported (`Ada`, not `ada`) |
| `matches 2 Storybook steps` | Word your Storybook step definitions so that one step matches only one |
| `can't be read: write its expression as a string literal` | Write the expression as a string literal, the first argument of `Given(…)` |
| `isn't a valid cucumber expression` | Fix the expression: cucumber's reason is in the parentheses |
| `the support file can't be parsed` | Fix the syntax error at that line: the plugin parses your support files to find the Storybook steps |

### No component is mounted in your story

```text
NoStoryMountedError: No component is mounted in your story.
```

Storybook's error, in its Interactions panel: a scenario plays an unmounted story
(`{storybook:storyUnmounted}`) and none of its steps mounts it. Call `mount()` in a step:
[Mounting](/guides/storybook/stories-and-steps#mounting).

## TypeScript

### An arrow function hook with a `world` argument doesn't type-check

```text
error TS2345: Argument of type '(world: CartWorld) => void' is not assignable to parameter of type 'TestCaseHookFunction<IWorld<any>>'.
  Types of parameters 'world' and 'arg' are incompatible.
```

TypeScript is reading Cucumber's own types for the hook: the plugin's types, which also type an
arrow function hook that takes the World, aren't in the project. Name them in the `tsconfig.json` that checks your
support code:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "types": ["@lotun/vitest-cucumber"]
  }
}
```

Steps never show this error: Cucumber types their arguments loosely. More:
[TypeScript](/guides/support-code#typescript).

## A bug in the plugin

A message that ends with `(a bug in @lotun/vitest-cucumber, please report it at
https://github.com/lotun-io/vitest-cucumber/issues)` is the plugin's own fault: please
[open an issue](https://github.com/lotun-io/vitest-cucumber/issues) with the whole error.
