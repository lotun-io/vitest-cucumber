# @lotun/vitest-cucumber

Run [Cucumber](https://cucumber.io/) feature files as [Vitest](https://vitest.dev/) tests.

You write Gherkin and step definitions with
[`@cucumber/cucumber`](https://github.com/cucumber/cucumber-js)'s API, as you would for Cucumber's
CLI. The plugin turns each feature file into a Vitest test file: every scenario, and every
row of a Scenario Outline, is a Vitest test. Vitest finds, filters, retries, runs and reports them;
your steps run with Cucumber's own semantics (step matching, hooks, World, timeouts, statuses).

```gherkin filename="features/cart.feature"
Feature: Cart
  Scenario: Adding an item
    Given an empty cart
    When I add "apples"
    Then the cart has 1 item
```

```ansi
 [32m✓[39m features/cart.feature [2m([22m[2m1 test[22m[2m)[22m[32m 65[2mms[22m[39m
   [32m✓[39m Cart [2m(1)[22m
     [32m✓[39m Adding an item[32m 9[2mms[22m[39m[0m
```

## Three ways to run

| Mode                                  | Your steps run in            | Use it for                                                     |
| ------------------------------------- | ---------------------------- | -------------------------------------------------------------- |
| [Node mode](/modes/node)              | a Vitest worker (Node.js)    | logic, APIs, services, or driving a browser with Playwright    |
| [Browser mode](/modes/browser)        | a real browser page, with [Vitest's browser mode](https://vitest.dev/guide/browser/) | the same steps in a real page: rendering and clicking in the DOM |
| [Storybook](/modes/storybook)         | a story's `play` function    | scenarios as Storybook stories, in Vitest and Storybook's UI   |

All three use the same plugin, the same `@cucumber/cucumber` imports and the same Gherkin.

## What you get from Vitest

- **[Filters](/guides/running#filtering)**: one scenario by its line, by Gherkin tags or by name.

  ```bash
  npx vitest run features/cart.feature             # one feature file
  npx vitest run features/cart.feature:2           # the scenario, outline or example row at line 2
  npx vitest run --tagsFilter "@smoke && !@slow"   # by Gherkin tag expression
  npx vitest run -t "Cart > Adding an item"        # by name: feature > rule > outline > scenario
  ```

- **[Watch mode](/guides/running#watch-mode)**: editing a feature file, a step definition or
  anything it imports reruns what depends on it.
- **[Parallel runs](/guides/running#parallel-runs)**: feature files spread across Vitest's workers.
- **[Retries](/guides/running#retries)**, **[bail](/guides/running#bail)**,
  **[coverage](/guides/running#coverage)**, Vitest's reporters and its UI.
- **[Failures at the Gherkin line](/guides/results#a-failing-step)**: a failing step's error points
  at its line in the feature file, and undefined steps come with
  [Cucumber's snippets](/guides/results#undefined-pending-and-ambiguous-steps).
