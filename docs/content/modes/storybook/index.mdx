# Storybook

List your feature files in Storybook's `stories`, and each one becomes a stories file of its own:
every scenario, and every row of a Scenario Outline, is a story that renders the story its steps
name (of the stories file its Background names), then plays the scenario's steps in its `play`
function. They run wherever
Storybook runs stories:

- **in Vitest**, with [Storybook's Vitest addon](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon):
  every scenario is a story test;
- **in Storybook's UI**: opening a scenario's story plays it, each Gherkin step a step in the
  Interactions panel;
- **in Storybook's UI, as tests**: the addon's testing widget runs the scenarios' story tests in
  Vitest ("Run tests"), and its watch mode runs them again as you save a feature file, its stories
  file or your support code;
- **in a static build** (`storybook build`), with no server.

Your stories files stay as they are: the plugin reads them, never changes them.

Works with Storybook 10 and every framework its Vitest addon supports (React, Vue, Svelte,
Angular, Web Components, …): [the full list](/reference/limitations#storybook-frameworks).

## Install

Start from a Storybook project with the Vitest addon
([`npx storybook add @storybook/addon-vitest`](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon)),
then add the plugin and Cucumber:

<Tabs items={["pnpm", "npm", "yarn"]}>
  <Tabs.Tab>
    ```bash
    pnpm add -D @lotun/vitest-cucumber@beta @cucumber/cucumber
    ```

  <Tabs.Tab>

## Configure

<Steps>

### Add the addon

```ts filename=".storybook/main.ts"
import { cucumber } from "@lotun/vitest-cucumber/storybook/node";
import type { StorybookConfig } from "@storybook/react-vite";

const config: StorybookConfig = {
  stories: [
    "../src/**/*.mdx",
    "../src/**/*.stories.@(js|jsx|mjs|ts|tsx)",
    // Feature files next to their stories files (src/) and in features/
    "../@(src|features)/**/*.@(feature|feature.md)",
  ],
  addons: [
    "@storybook/addon-vitest",
    cucumber({
      import: ["features/**/*.ts"],
    }),
  ],
  framework: "@storybook/react-vite",
};

export default config;
```

List your feature files in `stories` (`.feature`, and `.feature.md` for Markdown ones): each is a
stories file of its own, and story tests run them too. The pattern covers both places a feature file
may be in: next to its stories file, or in `features/`. With a `titlePrefix` on your entries:
[Title prefix](/guides/storybook/stories-and-steps#title-prefix).

`cucumber()` from `@lotun/vitest-cucumber/storybook/node` is the addon, with the plugin's
[options](/reference/options): Storybook and its story tests both use them. Write them inline, or
import them from a file of your own. `import` is resolved from the directory Storybook starts in,
your project's root.

### Keep `cucumber()` out of the Storybook test project

```ts filename="vite.config.ts"
/// <reference types="vitest/config" />
import { storybookTest } from "@storybook/addon-vitest/vitest-plugin";
import react from "@vitejs/plugin-react";
import { playwright } from "@vitest/browser-playwright";
import path from "node:path";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react()],
  test: {
    projects: [
      {
        extends: true,
        plugins: [
          storybookTest({ configDir: path.join(import.meta.dirname, ".storybook") }),
        ],
        test: {
          name: "storybook",
          browser: {
            enabled: true,
            headless: true,
            provider: playwright(),
            instances: [{ browser: "chromium" }],
          },
        },
      },
    ],
  },
});
```

Storybook's addon gives its test project the plugin from `.storybook/main.ts`, so the project has no
`cucumber()` of its own. A `cucumber()` there, or one in the root config that it inherits, fails
the run with a message saying so. An inline project inherits the config that declares it unless it
sets `extends: false`, so give the other projects their own `cucumber({ … })` in their own
`plugins`, or set `extends: false` on the Storybook project.

### Keep a classic preview

`.storybook/preview.ts(x)` exports a `Preview` object as usual. CSF factories (`definePreview`) are
not supported on Storybook 10.

### Add the plugin's types

In a TypeScript project, name the plugin's types in the `tsconfig.json` that checks your support
code:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "types": ["@lotun/vitest-cucumber"]
  }
}
```

They type Cucumber's hooks for arrow functions that take the World:
[TypeScript](/guides/support-code#typescript).
