# Storybook

List your feature files in Storybook's `stories`, and each one becomes a stories file of its own:
every scenario, and every row of a Scenario Outline, is a story that renders a story of the
stories file next to it, then plays the scenario's steps in its `play` function. They run wherever
Storybook runs stories:

- **in Vitest**, with [Storybook's Vitest addon](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon):
  every scenario is a story test;
- **in Storybook's UI**: opening a scenario's story plays it, each Gherkin step a step in the
  Interactions panel;
- **in Storybook's UI, as tests**: the addon's testing widget runs the scenarios' story tests in
  Vitest ("Run tests"), and its watch mode runs them again as you save a feature file, its stories
  file or your support code;
- **in a static build** (`storybook build`), with no server.

Your stories files stay as they are: the plugin reads them, never changes them.

Works with Storybook 10 and every framework its Vitest addon supports: see [Frameworks](#frameworks).

## Install

Start from a Storybook project with the Vitest addon
([`npx storybook add @storybook/addon-vitest`](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon)),
then add the plugin and Cucumber:

<Tabs items={["pnpm", "npm", "yarn"]}>
  <Tabs.Tab>
    ```bash
    pnpm add -D @lotun/vitest-cucumber@beta @cucumber/cucumber
    ```

## Configure

<Steps>

### Add the addon

```ts filename=".storybook/main.ts"
import { cucumber } from "@lotun/vitest-cucumber/storybook/node";
import type { StorybookConfig } from "@storybook/react-vite";

const config: StorybookConfig = {
  stories: [
    "../src/**/*.mdx",
    "../src/**/*.stories.@(js|jsx|mjs|ts|tsx)",
    // Feature files next to their stories files (src/) and in features/
    "../@(src|features)/**/*.@(feature|feature.md)",
  ],
  addons: [
    "@storybook/addon-vitest",
    cucumber({
      import: ["features/**/*.ts"],
    }),
  ],
  framework: "@storybook/react-vite",
};

export default config;
```

List your feature files in `stories` (`.feature`, and `.feature.md` for Markdown ones): each is a
stories file of its own. Story tests run what `stories` lists too. The pattern covers both places a
feature file may be in: [next to its stories file, or in `features/`](/modes/storybook/features#feature-files-become-stories).

`cucumber()` from `@lotun/vitest-cucumber/storybook/node` is the addon, with the plugin's
[options](/reference/options): Storybook and its story tests both use them. Write them inline, or
import them from a file of your own. `import` is resolved from the directory Storybook starts in,
your project's root.

### Keep `cucumber()` out of the Storybook test project

```ts filename="vite.config.ts"
/// <reference types="vitest/config" />
import { storybookTest } from "@storybook/addon-vitest/vitest-plugin";
import react from "@vitejs/plugin-react";
import { playwright } from "@vitest/browser-playwright";
import path from "node:path";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [react()],
  test: {
    projects: [
      {
        extends: true,
        plugins: [
          storybookTest({ configDir: path.join(import.meta.dirname, ".storybook") }),
        ],
        test: {
          name: "storybook",
          browser: {
            enabled: true,
            headless: true,
            provider: playwright(),
            instances: [{ browser: "chromium" }],
          },
        },
      },
    ],
  },
});
```

Storybook's addon gives its test project the plugin from `.storybook/main.ts`, so the project has no
`cucumber()` of its own. A `cucumber()` there, or one in the root config that it inherits, fails
the run with a message saying so. An inline project inherits the config that declares it unless it
sets `extends: false`, so give the other projects their own `cucumber({ … })` in their own
`plugins`, or set `extends: false` on the Storybook project.

### Keep a classic preview

`.storybook/preview.ts(x)` exports a `Preview` object as usual. CSF factories (`definePreview`) are
not supported on Storybook 10.

</Steps>

## Title prefix

If your `stories` entries have a `titlePrefix`, give the feature files' entries the same prefix as
the stories files' entry:

```ts filename=".storybook/main.ts"
stories: [
  { directory: "../src", files: "**/*.stories.@(js|jsx|mjs|ts|tsx)", titlePrefix: "App" },
  // Feature files next to their stories files
  { directory: "../src", files: "**/*.@(feature|feature.md)", titlePrefix: "App" },
  // Feature files in features/
  { directory: "../features", files: "**/*.@(feature|feature.md)", titlePrefix: "App" },
],
```

Storybook puts an entry's prefix in front of the title of every file that entry matches, and a
feature file is matched by its own entry, wherever its stories file is. With the same prefix on
each, a feature is listed under its stories file (`App/Example/Greeting`, then
`Feature: Greeting`). Without it on a features' entry, those features are listed outside `App`,
apart from their stories files.

An entry has one prefix: with stories files under several prefixes, keep the features of each in a
folder of their own, with an entry and its prefix (`features/app` with `App`, `features/admin`
with `Admin`).

## Frameworks

Storybook's Vitest addon runs story tests with Storybook's Vite builder only, and its setup accepts
these frameworks. The plugin supports the same list.

| Framework | Package |
| --- | --- |
| React | `@storybook/react-vite` |
| Next.js | `@storybook/nextjs-vite` |
| React Native Web | `@storybook/react-native-web-vite` |
| TanStack React | `@storybook/tanstack-react` |
| Preact | `@storybook/preact-vite` |
| Vue 3 | `@storybook/vue3-vite` |
| Svelte | `@storybook/svelte-vite` |
| SvelteKit | `@storybook/sveltekit` |
| Angular | `@storybook/angular-vite` |
| Web Components | `@storybook/web-components-vite` |
| HTML | `@storybook/html-vite` |
| SolidJS | `storybook-solidjs-vite` (community) |

<Callout type="info">
  **SolidJS**: `vite-plugin-solid` sets Vitest's `environment` to `jsdom` unless you set one, and
  Vitest stops with "Cannot find dependency 'jsdom'" if it isn't installed, even though story tests
  run in the browser. Install `jsdom`, or set `test.environment` in the Storybook test project.
</Callout>

### Not supported

- **Webpack frameworks** (`@storybook/nextjs`, `@storybook/angular`, `@storybook/react-webpack5`,
  `@storybook/vue3-webpack5`, …): the plugin is a Vite plugin, and the Vitest addon needs Vite too.
  Next.js and Angular have Vite frameworks: `@storybook/nextjs-vite`, `@storybook/angular-vite`.
- **Vite frameworks the addon doesn't accept**, such as the community frameworks for Analog, Astro
  and Nuxt: scenarios run as the addon's story tests, so a framework the addon doesn't support isn't
  supported here either.
- **React Native on a device** (`@storybook/react-native`): no Vite, no Vitest addon.
