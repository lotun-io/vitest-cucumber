## Filters

```bash
npx vitest run features/greeting.feature      # one feature file
npx vitest run features/greeting.feature:4    # the scenario at line 4
npx vitest run --tagsFilter "@smoke"          # by Gherkin tag
npx vitest run -t "Greeting > Saying hello"   # by name
```

More, with retries, bail, watch mode and coverage: [Running and filtering](/guides/running).

## Specific to browser mode

- **Every browser instance runs every scenario**, each with its own `BeforeAll`, Worlds and
  attachments. Add instances to run your features in several browsers:

  ```ts
  instances: [{ browser: "chromium" }, { browser: "firefox" }, { browser: "webkit" }],
  ```

- **`BeforeAll` and `AfterAll` run once per page**: once per feature file with Vitest's default
  `isolate: true`. See [BeforeAll and AfterAll](/guides/support-code#beforeall-and-afterall).
- **[Worker variables](/guides/support-code#worker-variables)** are on `import.meta.env`, not
  `process.env`: `import.meta.env.CUCUMBER_WORKER_ID`. A page's `VITEST_WORKER_ID` and
  `VITEST_POOL_ID` are its slot, shared by the pages that use it in turn.
- **[Attachments](/guides/support-code#attachments) are strings only.** For binary data, attach
  base64 with a `base64:` media type: `world.attach(base64, "base64:image/png")`.
- **Not available in the page**: Cucumber's JavaScript API (`@cucumber/cucumber/api`) and its
  formatter and runner classes. See [Limitations](/reference/limitations#in-a-page-browser-mode-and-storybook).
- **A page that reloads or crashes** during a run fails its feature file instead of hanging.
- **Vitest's module cache is off for the project.** The plugin sets
  [`fsModuleCache: false`](https://vitest.dev/config/fsmodulecache) on a browser project (and on a
  Storybook project). Vitest only uses that cache there for `vitest list` and `--changed`, where it
  could read an outdated copy of a feature's module. Your other projects keep their cache.

<Callout type="warning">
  If a package your steps import makes Vite optimize new dependencies mid-run (the page reloads and
  the run fails), add it to [`optimizeDeps.include`](https://vite.dev/config/dep-optimization-options)
  in your config.
</Callout>
