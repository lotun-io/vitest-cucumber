`npx vitest` watches instead: a saved feature file, step definition or module one imports reruns
what depends on it.

## Filters

```bash
npx vitest run features/greeting.feature      # one feature file
npx vitest run features/greeting.feature:4    # the scenario at line 4
npx vitest run --tagsFilter "@smoke"          # by Gherkin tag
npx vitest run -t "Greeting > Saying hello"   # by name
```

More, with retries, bail, watch mode and coverage: [Running and filtering](/guides/running).

## Specific to node mode

- **`BeforeAll` and `AfterAll` run once per Vitest worker**: once per feature file with Vitest's
  default `isolate: true`, once for all a worker's files with `isolate: false`. See
  [BeforeAll and AfterAll](/guides/support-code#beforeall-and-afterall).
- **[Worker variables](/guides/support-code#worker-variables)** are on `process.env`.
- **[Attachments](/guides/support-code#attachments)** can be strings, `Buffer`s or readable streams
  (with a media type).
- **Cucumber's JavaScript API** (`@cucumber/cucumber/api`, e.g. `runCucumber`) works from a step, as
  plain Cucumber.
- **Pools**: `forks` (Vitest's default) and `threads`.
