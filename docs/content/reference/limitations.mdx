# Limitations

## Not supported

In every mode:

| What | What happens | Use instead |
| --- | --- | --- |
| `BeforeAll`/`AfterAll` with `on: "COORDINATOR"` | Defining one fails: `BeforeAll({ on: "COORDINATOR" }) isn't supported, use Vitest's globalSetup for once-per-run setup` | Vitest's [`globalSetup`](https://vitest.dev/config/globalsetup), for once-per-run setup |
| `setDefaultTimeout` | Calling it throws | Vitest's `testTimeout` and `hookTimeout`, or a definition's [`timeout`](/guides/support-code#timeouts) |
| `setParallelCanAssign` | Calling it throws | Nothing: Vitest decides which worker runs which feature file |
| Cucumber's formatters, plugins and publishing | The options are ignored | Vitest's [reporters](https://vitest.dev/guide/reporters) |
| Cucumber's configuration files and profiles | They aren't read | Your Vitest config: [Options](/reference/options#cucumbers-options) |
| Concurrent scenarios | A worker runs its scenarios one at a time, whatever `concurrent` says | Feature files run in parallel across workers |
| Vitest's `vmThreads` and `vmForks` pools | Not tested | `forks` (the default) or `threads` |

## Different from Cucumber's CLI

- **`test.include` and `import` have no defaults**: set both.
- **`BeforeAll`/`AfterAll` run per worker**, so per feature file unless `isolate: false`:
  [BeforeAll and AfterAll](/guides/support-code#beforeall-and-afterall).
- **Timeouts** are per step and hook, as Cucumber's, Vitest's `testTimeout` and `hookTimeout` their
  defaults: [Timeouts](/guides/support-code#timeouts).
- **A feature file with no scenarios** fails (`No test found in suite`).
- **A hook's `result` is a copy**: writing to it doesn't change a scenario's outcome, which
  Cucumber doesn't support either ([cucumber-js#1724](https://github.com/cucumber/cucumber-js/issues/1724)).

## In a page (browser mode and Storybook)

- Attachments are strings only: [Attachments](/guides/support-code#attachments).
- `@cucumber/cucumber/api` and Cucumber's formatter and runner exports (`Formatter`,
  `SummaryFormatter`, …) throw: the page runs the plugin's own copy of Cucumber's runtime.

## Node mode with `isolate: false`

A failing `AfterAll` hook's error is lost and doesn't fail the run: Vitest 5.1 drops an error thrown
while a worker shuts down
([vitest-dev/vitest#11763](https://github.com/vitest-dev/vitest/issues/11763)). With Vitest's
default `isolate: true`, it's reported as usual.

## Storybook

- Storybook 10, with the [frameworks](#storybook-frameworks) its Vitest addon supports (Vite
  only); classic previews only (not `definePreview`).
- A feature file needs one stories file, which its Background names (a stories file step), and
  each scenario a story step: [Storybook steps](/guides/storybook/stories-and-steps#storybook-steps). The
  stories file is CSF 3 written in JavaScript or TypeScript (one with only a meta is enough),
  its `tags` and `title` written as literals. Not CSF factories, `.stories.svelte` or `.stories.vue`:
  [Stories files a feature can use](/guides/storybook/stories-and-steps#stories-files-a-feature-can-use).
- A stories file that no pattern of Storybook's `stories` matches needs a `title` written in its
  meta: its features are listed under its title.

## Storybook frameworks

Storybook's Vitest addon runs story tests with Storybook's Vite builder only, and its setup accepts
these frameworks. The plugin supports the same list.

| Framework | Package |
| --- | --- |
| React | `@storybook/react-vite` |
| Next.js | `@storybook/nextjs-vite` |
| React Native Web | `@storybook/react-native-web-vite` |
| TanStack React | `@storybook/tanstack-react` |
| Preact | `@storybook/preact-vite` |
| Vue 3 | `@storybook/vue3-vite` |
| Svelte | `@storybook/svelte-vite` |
| SvelteKit | `@storybook/sveltekit` |
| Angular | `@storybook/angular-vite` |
| Web Components | `@storybook/web-components-vite` |
| HTML | `@storybook/html-vite` |
| SolidJS | `storybook-solidjs-vite` (community) |

<Callout type="info">
  **SolidJS**: `vite-plugin-solid` sets Vitest's `environment` to `jsdom` unless you set one, and
  Vitest stops with "Cannot find dependency 'jsdom'" if it isn't installed, even though story tests
  run in the browser. Install `jsdom`, or set `test.environment` in the Storybook test project.
</Callout>

Not supported:

- **Webpack frameworks** (`@storybook/nextjs`, `@storybook/angular`, `@storybook/react-webpack5`,
  `@storybook/vue3-webpack5`, …): the plugin is a Vite plugin, and the Vitest addon needs Vite too.
  Next.js and Angular have Vite frameworks: `@storybook/nextjs-vite`, `@storybook/angular-vite`.
- **Vite frameworks the addon doesn't accept**, such as the community frameworks for Analog, Astro
  and Nuxt: scenarios run as the addon's story tests, so a framework the addon doesn't support isn't
  supported here either.
- **React Native on a device** (`@storybook/react-native`): no Vite, no Vitest addon.

## File names

A feature file's name can't contain `?` (Vite reads it as a query).
