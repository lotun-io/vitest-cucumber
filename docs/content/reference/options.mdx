# Options

```ts
import { cucumber, type CucumberOptions } from "@lotun/vitest-cucumber";

cucumber(options?: CucumberOptions)
```

`CucumberOptions` is a subset of Cucumber's
[configuration](https://github.com/cucumber/cucumber-js/blob/main/docs/configuration.md), with the
same meaning:

| Option            | Type       | Default | |
| ----------------- | ---------- | ------- | - |
| `import`          | `string[]` | none    | Support code: globs or folders, relative to the project's root |
| `strict`          | `boolean`  | `true`  | `false`: a pending step skips its scenario instead of failing it |
| `dryRun`          | `boolean`  | `false` | Match steps without running anything |
| `backtrace`       | `boolean`  | `false` | Keep Cucumber's and the plugin's frames in errors |
| `language`        | `string`   | `"en"`  | The default Gherkin language (`# language:` in a file wins) |
| `worldParameters` | `object`   | `{}`    | Each World's `this.parameters`; must be JSON |

## Config file

Instead of passing the options to `cucumber()`, you can keep them in `cucumber.config.ts` in the
project's root, as its default export, and call `cucumber()` with no options:

```ts filename="cucumber.config.ts"
import type { CucumberOptions } from "@lotun/vitest-cucumber";

export default {
  import: ["features/**/*.ts"],
} satisfies CucumberOptions;
```

```ts filename="vitest.config.ts"
plugins: [cucumber()],
```

- **One or the other**: `cucumber()` with no options reads the file; `cucumber(options)` uses those
  options and doesn't read it. To use another file, import it: `cucumber(options)` with
  `import options from "./e2e/cucumber.config.ts"`.
- **Its name**: `cucumber.config` with one of these extensions, the first found in this order:
  `.ts`, `.mts`, `.cts`, `.js`, `.mjs`, `.cjs`, `.json`. In `.cts` and `.cjs` it's
  `module.exports = { … }`. A JSON file holds the options object itself.
- **The project's root**: each Vitest project's `root`. Several projects with the same root share
  the file, whether each has its own `cucumber()` or they all inherit one from the root config.
- **In Storybook**, the options are always `.storybook/cucumber.config.ts` (your Storybook config
  folder's): options passed to `cucumber()` there aren't used.
  [Setup](/modes/storybook#put-the-options-in-storybookcucumberconfigts).
- **Node loads it as it is**, with its own TypeScript support: erasable syntax only (no `enum`), imports
  with their extension, no `paths` aliases. In a project without `"type": "module"`, name it
  `cucumber.config.mts`.
- **Each run reads it again**: in watch mode, an edit applies from the next rerun (saving the file
  alone doesn't start one). Modules it imports keep their first version until Vitest restarts.

## import

Your step definitions, hooks, World and parameter types. A folder means every `.ts`, `.mts`, `.cts`,
`.tsx`, `.js`, `.mjs`, `.cjs` and `.jsx` file in it. Files load once each, in order: each glob's
matches sorted, globs in your order.

There's no default: without `import` (or with globs matching no file), nothing loads and every step
is undefined, with snippets.

## strict

With `strict: false`, a scenario with a pending step is a skipped test, its note
`Pending step: When …`, and doesn't fail the run.

## dryRun

Every scenario is a skipped test and no step or hook runs. An undefined or ambiguous step is its
test's note (`Undefined step: …`, `Ambiguous step: …`): a quick way to check every step is defined.

## backtrace

Errors hide frames from Cucumber and the plugin. `backtrace: true` keeps every frame.

## Cucumber's options

Every option of Cucumber's configuration, and what to use here:

| Cucumber option | | Use |
| --- | :-: | --- |
| `import` | ✅ | |
| `strict` | ✅ | |
| `dryRun` | ✅ | |
| `backtrace` | ✅ | |
| `language` | ✅ | |
| `worldParameters` | ✅ | |
| `paths` | 🔀 | `test.include`, and files on the command line |
| `tags` | 🔀 | `--tagsFilter` |
| `name` | 🔀 | `-t` / `--testNamePattern` |
| `retry`, `retryTagFilter` | 🔀 | `test.retry`, and `retry` in `test.tags` |
| `parallel` | 🔀 | `test.maxWorkers` |
| `failFast` | 🔀 | `--bail` |
| `order` | 🔀 | `test.sequence.shuffle` (`--sequence.shuffle`) |
| `shard` | 🔀 | `--shard`, which splits by feature file |
| `format`, `formatOptions` | 🔀 | `test.reporters` |
| `require` | 🔀 | the plugin's [`import`](#import) |
| `requireModule`, `loader` | 🔀 | not needed: Vite transforms TypeScript |
| `forceExit` | 🔀 | not needed: Vitest ends the run itself |
| `workerOptions` | 🔀 | `test.execArgv`: Node's flags for each worker, such as `--max-old-space-size=2048` (with the default `forks` pool) |
| `plugin`, `pluginOptions` | ❌ | |
| `publish` | ❌ | |

- ✅ **Supported**, with Cucumber's meaning.
- 🔀 **Not supported, use Vitest's alternative.**
- ❌ **Not supported.**

An option that isn't supported is ignored, and so are Cucumber's configuration files (`cucumber.js`,
`cucumber.mjs`, …) and profiles: configure per environment in your Vitest config instead.
